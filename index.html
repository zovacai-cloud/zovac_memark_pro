ZOVAC. Memark Pro

Personal Build Guide — Local Use Only
FOR PERSONAL USE ONLY

This guide is for building ZOVAC on your laptop for your own videos. No database, no web server, no React frontend. Just: screen recording → Gemini Gem conversation → YAML script → Python engine → polished video.

What You're Building

A simple workflow with 3 components:

1. Gemini Gem (Script Composer)
You describe your video idea in plain English. The Gem interviews you and outputs a YAML script.
2. Region Helper (Python Script)
Click-and-drag on a video frame to define regions. Saves coordinates to JSON automatically.
3. Pixel Engine (Python)
Reads YAML + video + regions + brand. Renders a cinematic MP4 with zooms, effects, and subtitles.
WHAT'S REMOVED FROM THE ORIGINAL SPEC

The master scope was designed for a SaaS product serving multiple users. For personal use, we're removing:

  • All database code (MySQL, Drizzle ORM, schema.ts, migrations)
  • All API code (Hono server, tRPC routers, HTTP endpoints)
  • All React frontend code (Dashboard, ProjectEditor, BrandManager, VideoLibrary)
  • File upload system (You just point to local files)
  • Render queue & job tracking (You run one command, wait, done)
  • Multi-format exports (We'll start with just 16:9, add 9:16/1:1 later if needed)

System Requirements

Software You Need

  1. Python 3.10+ — python3 --version to check
  2. FFmpeg — ffmpeg -version to check. If missing: brew install ffmpeg (Mac) or download from ffmpeg.org
  3. pip packages: pip install opencv-python pillow pyyaml --break-system-packages
  4. A text editor — VS Code, Sublime, Notepad++, or even TextEdit/Notepad
  5. Google AI Studio account — Free at aistudio.google.com (for creating the Gemini Gem)

Hardware

  • Any laptop from the last 5 years
  • At least 8GB RAM (16GB recommended)
  • ~2GB free disk space per project
RENDERING SPEED EXPECTATIONS

A 40-second video with 4 scenes takes about 2-4 minutes to render on a modern laptop (M1 MacBook Air, 2020 ThinkPad, etc). Older machines may take 5-10 minutes. This is normal — you're processing every frame.

Build Steps

1 Build the Region Helper

This is a simple script using OpenCV's built-in selectROI function. It lets you click-and-drag to define regions on a video frame.

What to Create:

helpers/region_helper.py

import cv2
import json
import sys

def select_regions(video_path, output_json_path):
    """
    Opens a video frame, lets user draw regions, saves to JSON.
    Usage: python region_helper.py source.mp4 regions.json
    """
    # Open video
    cap = cv2.VideoCapture(video_path)
    
    # Seek to 0.5 seconds in (to avoid black frames)
    fps = cap.get(cv2.CAP_PROP_FPS)
    cap.set(cv2.CAP_PROP_POS_FRAMES, int(fps * 0.5))
    
    ret, frame = cap.read()
    if not ret:
        print("❌ Could not read video frame")
        sys.exit(1)
    
    cap.release()
    
    regions = {}
    
    print("\n📦 ZOVAC Region Helper")
    print("━" * 50)
    print("Instructions:")
    print("  • Click and drag to draw a box")
    print("  • Press ENTER to confirm")
    print("  • Press C to cancel current region")
    print("  • Close window when done")
    print("━" * 50)
    
    while True:
        region_name = input("\nRegion name (or press Enter to finish): ").strip()
        
        if not region_name:
            break
        
        print(f"\n🎯 Draw region: {region_name}")
        print("   (Click-drag on the video frame, then press ENTER)")
        
        # Let user select ROI
        bbox = cv2.selectROI("Select Region", frame, fromCenter=False, showCrosshair=True)
        
        if bbox[2] > 0 and bbox[3] > 0:  # Valid selection
            regions[region_name] = {
                "x": int(bbox[0]),
                "y": int(bbox[1]),
                "w": int(bbox[2]),
                "h": int(bbox[3])
            }
            print(f"   ✅ Saved: {bbox}")
        else:
            print(f"   ⚠️  Skipped (no selection)")
    
    cv2.destroyAllWindows()
    
    # Save to JSON
    with open(output_json_path, 'w') as f:
        json.dump(regions, f, indent=2)
    
    print(f"\n✅ Saved {len(regions)} regions to {output_json_path}")
    for name, coords in regions.items():
        print(f"   • {name}: {coords}")

if __name__ == "__main__":
    if len(sys.argv) != 3:
        print("Usage: python region_helper.py VIDEO_PATH OUTPUT_JSON")
        print("Example: python region_helper.py ../projects/demo/source.mp4 ../projects/demo/regions.json")
        sys.exit(1)
    
    select_regions(sys.argv[1], sys.argv[2])

2 Build the Gemini Gem

The Gem is just a system prompt you paste into Google AI Studio. I'll give you the complete prompt below.

Steps:

  1. Go to aistudio.google.com
  2. Click "New Gem" (or "Create New" → "Gem")
  3. Paste the system prompt below into the instructions field
  4. Name it: "ZOVAC Script Composer"
  5. Save

The System Prompt:

# ZOVAC Script Composer — System Prompt

You are a creative video director helping users create YAML scripts for ZOVAC Memark Pro, a tool that turns boring screen recordings into polished product videos with smooth zooms, callout boxes, and animated text.

## Your Role
Interview the user in plain English about their video idea, then output a complete YAML script they can use.

## Conversation Flow (4 Phases)

### Phase 1: Project Basics
Ask:
- "What's the name of your project?"
- "What's your screen recording file called?" (default: source.mp4)
- "What should the final video be called?" (slug version of project name)
- "What frame rate? 24fps (cinematic), 30fps (standard), or 60fps (smooth)?" (default: 30)
- "Resolution? Usually 1920x1080 is perfect." (default: 1920x1080)

### Phase 2: The Story
Ask: "Tell me about your video. Walk me through what happens in the recording like you're describing it to a friend. What's the main message?"

Listen for:
- What problem does the tool solve?
- What's the "wow" moment?
- What should viewers feel?

### Phase 3: Scene by Scene
For each scene the user describes:

Ask:
- "When does this happen? Like 0:05 to 0:12." (time format: M:SS - M:SS)
- "Do you want to show the whole screen or zoom into something specific?"
  - If zoom: "What region? (You'll draw this later in the region helper)"
  - If zoom: "How close? 1.5x is subtle, 3x is very close."
- "What should the subtitle say?"
- "How should the text appear? Fade in word-by-word (smooth), typewriter (classic), slide up (energetic), or just fade in?"
- "How should this scene end? Crossfade (smooth), wipe (directional), zoom blur (dramatic), or flash cut (punchy)?"

For effects, proactively suggest:
- Callout box: "Want a glowing box around that button?"
- Spotlight: "Want everything else dimmed so this stands out?"
- Arrow: "Want an arrow pointing to it with a label?"

Default to smooth, professional choices:
- Easing: cubic_ease_in_out
- Transition duration: 0.3s
- Subtitle position: bottom_center

### Phase 4: Review & Generate
Summarize all scenes in plain English. Ask: "Does this sound right?"

Then output:
1. Complete YAML script
2. List of region names they need to define: "Before rendering, use region_helper.py to draw these regions: [list]"

## Valid YAML Values (MEMORIZE THESE)

**Easing:** linear, ease_in, ease_out, ease_in_out, cubic_ease_in_out, ease_in_out_sine, spring, bounce_out

**Visual type:** fullscreen, zoom, pan, dolly_in, dolly_out

**Effect type:** callout_box, annotation_arrow, spotlight, motion_blur

**Subtitle style:** fade_in, fade_in_word_by_word, typewriter, slide_up, highlight_current_word

**Subtitle position:** top_center, center, bottom_center, top_left, bottom_left

**Transition type:** crossfade, smooth_zoom_in, zoom_out_blur, zoom_blur_push, wipe_left, wipe_up, flash_cut, none

**Zoom level:** 1.0 to 5.0 (default: 2.0)

**Duration format:** Float + "s" (e.g., "0.6s")

**Time format:** M:SS - M:SS or HH:MM:SS - HH:MM:SS

## YAML Template Structure

```yaml
zovac_schema_version: "1.0"

project:
  name: "Project Name"
  source_video: "source.mp4"
  output_name: "project_name_slug"
  fps: 30
  resolution: "1920x1080"
  export_formats:
    - "16:9"
  brand_profile: "default"

scenes:
  - id: "intro"
    time: "0:00 - 0:05"
    visual:
      type: "fullscreen"
    subtitle:
      text: "Your subtitle here"
      style: "fade_in_word_by_word"
      position: "bottom_center"
    transition_out:
      type: "crossfade"
      duration: "0.3s"

  - id: "feature_zoom"
    time: "0:05 - 0:15"
    visual:
      type: "zoom"
      target: "search_bar"
      zoom_level: 2.5
      easing: "cubic_ease_in_out"
    effects:
      - type: "callout_box"
        target: "search_bar"
        color: "#6C4EF5"
        animated_stroke: true
        stroke_duration: "0.6s"
    subtitle:
      text: "Find anything instantly"
      style: "typewriter"
      position: "bottom_center"
    transition_out:
      type: "zoom_blur_push"
      duration: "0.5s"
```

## Personality Rules
- Friendly and warm, not robotic
- Ask 1-2 questions at a time max
- Rephrase technical terms into plain English
- After each scene, confirm with a human summary
- Mention smart defaults you're applying
- Never show YAML until the end
- Be encouraging — "This is going to look great!"

## Region Handling
When a user says they want to zoom to "the dashboard" or "the search bar", add that as a region target in the YAML. Then at the end, tell them:

"Before rendering, run the region helper to draw these regions: [list]. The helper will let you click-and-drag boxes on your video frame."

Begin by warmly greeting the user and asking about their project name.
✅ EXIT CRITERIA

You can have a full conversation with the Gem, describe a 3-scene video, and it outputs valid YAML with correct syntax. Test it by copying the output YAML and checking that all field names match the template.

3 Build the Pixel Engine

This is the most complex step. The engine has 10 Python files working together. I'll guide you through building them one by one.

REALISTIC TIMELINE

If you're working with me (Claude) to build this: 2-4 weeks of steady work. We'll build one module at a time, test it, then move to the next. I'll write all the code — you just run it and tell me what breaks.

Build Order:

  1. validator.py — Script validation (1 day)
  2. script_parser.py — YAML parsing + time parsing (1 day)
  3. brand.py — Brand config with defaults (1 day)
  4. motion.py — Zoom/pan with easing curves (2-3 days)
  5. subtitles.py — Text rendering with animations (2-3 days)
  6. effects.py — Callout box, arrow, spotlight (3-4 days)
  7. transitions.py — Crossfade, wipe using FFmpeg xfade (2 days)
  8. compositor.py — Frame-by-frame assembly (3-4 days)
  9. exporter.py — Final MP4 packaging (1 day)
  10. render.py — CLI entry point tying it all together (1 day)

We start with the simplest piece and prove it works before moving on.

FIRST MILESTONE: Validator + Parser

Once validator.py and script_parser.py work, you can run:

python -c "from script_parser import parse_script; print(parse_script('test.yaml'))"

And it will print your parsed script structure. That's proof the foundation works.

Daily Usage (Once Built)

After everything is built, your workflow is:

  1. Record your screen

  2. Talk to the Gem

From screen recording to polished output in under 30 minutes. Steps 1-3 take ~15 minutes. Rendering takes ~3 minutes. Iteration (tweaking YAML) takes ~10 minutes.
