PERSONAL LOCAL Product Vision

FOR PERSONAL USE ONLY — NO HOSTING, NO DATABASE, NO CLOUD

This version of ZOVAC Memark Pro is designed for one user on one laptop. You record your screen, chat with a Gemini Gem to get a script, click-and-drag to define regions, and run a Python command to get a polished video. Everything stays on your machine. No accounts, no subscriptions, no internet required after setup.

1.1 The Problem

You have built software tools. You want to show their impact in videos. But raw screen recordings are boring. Professional video editing takes weeks to learn and hours per video. You need a way to turn a 30-second screen recording into a Google-quality product showcase in under 30 minutes.

1.2 The Solution

A local Python application with three parts:

  1. Talk to a Gem — Describe your video in plain English. It writes the script.
  2. Draw regions — Click-and-drag on your video frame to mark important UI elements.
  3. Run a command — The engine renders zooms, effects, subtitles, and transitions.

1.3 The Core Promise

THE 30-MINUTE PROMISE

From screen recording to polished product video in under 30 minutes.

Record (5 min) → Chat with Gem (10 min) → Draw regions (5 min) → Render (3 min) → Tweak and re-render (5 min) → Done.

1.4 What We Are NOT Building

EXPLICIT EXCLUSIONS
  • No database — Projects are folders on disk, not rows in MySQL.
  • No web server — No Hono, no tRPC, no HTTP endpoints.
  • No React frontend — Your text editor + terminal + browser (for Gem chat) is the UI.
  • No user accounts — It is just you. No login, no auth.
  • No cloud rendering — Everything happens on your CPU. No AWS, no queue.
  • No file upload system — You copy files to a folder. That is it.
  • No render queue — You run one command, wait, done. No polling.
  • No multi-user anything — Single user, single machine.

FEATURE The Preview System

2.1 Why Preview Is Essential

Without preview, your workflow is: write script → wait 4 minutes → discover zoom is wrong → edit script → wait 4 minutes → discover text is too small → edit script → wait 4 minutes. You give up after 2 iterations.

With preview: write script → wait 30 seconds → see result → edit script → wait 30 seconds → see result. You iterate 10 times in 10 minutes and get a perfect video.

HOW PREVIEW WORKS — THE FULL EXPLANATION

Preview Mode is a fast, low-resolution render of a subset of your video. It is not magic. It is the same engine running with optimized settings:

  • Resolution drops to 960×540 — Quarter of Full HD = 4× fewer pixels to process
  • Frame rate drops to 24fps — Instead of 60fps = 2.5× fewer frames
  • Max duration capped at 20 seconds — Even if your script says 2 minutes
  • FFmpeg preset: ultrafast — Sacrifices compression for speed
  • Effects simplified — No motion blur, basic subtitle fade instead of per-character animation

Result: A 20-second preview renders in ~30 seconds instead of ~4 minutes.

2.2 Preview Commands

# Preview the ENTIRE script (first 20 seconds only)
python engine/render.py \
  --script projects/demo/script.yaml \
  --regions projects/demo/regions.json \
  --output-dir projects/demo/output \
  --preview

# Preview a SINGLE scene by its ID
python engine/render.py \
  --script projects/demo/script.yaml \
  --regions projects/demo/regions.json \
  --output-dir projects/demo/output \
  --scene search_bar_demo \
  --preview

# Preview a SINGLE cut by its ID
python engine/render.py \
  --script projects/demo/script.yaml \
  --regions projects/demo/regions.json \
  --output-dir projects/demo/output \
  --cut search_demo \
  --preview

# Preview MULTIPLE cuts together
python engine/render.py \
  --script projects/demo/script.yaml \
  --regions projects/demo/regions.json \
  --output-dir projects/demo/output \
  --cut intro_problem,search_demo \
  --preview

2.4 The Iteration Workflow

STEP-BY-STEP ITERATION

1. Chat with Gem → get YAML → save to script.yaml

2. Preview scene 1: --scene intro --preview → watch → adjust YAML

5. Preview all together: --cut intro,search_demo,dashboard --preview → watch flow

6. Full render: remove --preview and --scene/--cut → wait 3-4 minutes → done

FEATURE Cuts and Granular Preview

3.1 What Are Cuts?

A cut is a user-defined segment of the source video with a label. Cuts let you break a long video into manageable pieces, focus on one piece at a time, and preview/render them independently.

# Step 2: Edit script.yaml
# Change: zoom_level: 2.5 -> zoom_level: 1.8
# Change: easing: cubic_ease_in_out -> easing: spring

# Output: preview_cut_search_demo.mp4 (overwritten with new version)
# You watch it. Perfect.

# Step 4: Move to next cut
python engine/render.py ... --cut dashboard_wow --preview

# Step 5: When all cuts are perfect, preview them together

# Step 6: Full quality render
python engine/render.py \
  --script projects/demo/script.yaml \
  --regions projects/demo/regions.json \
  --output-dir projects/demo/output

# Output: myapp_showcase_master.mp4 (full quality, all cuts assembled)

3.4 Cut Assembly Rules

  • Order matters: Cuts are assembled in the order they appear in the cuts: list.
  • Time ranges must not overlap: Cut A ends at 0:05, Cut B starts at 0:05. No gaps, no overlaps.
  • Scenes within a cut: A cut can contain multiple scenes. All scenes in a cut are rendered together with their transitions.
  • Cut-to-cut transitions: The last scene of Cut A and the first scene of Cut B are joined with the last scene's transition_out settings.
  • Missing cuts: If cuts: is omitted, the engine treats each scene as its own cut.
WHY CUTS ARE BETTER THAN SCENES ALONE

Scenes are granular (5-10 seconds each). Previewing one scene at a time means you lose context — you cannot see how the transition from Scene 2 to Scene 3 feels.

Cuts are logical chunks (5-15 seconds, 1-3 scenes each). Previewing a cut shows you the flow within a narrative beat — the problem, the solution, the proof. This is the right granularity for creative iteration.

FEATURE Smart Layout Options

4.1 The Problem: 16:9 Source to 9:16 Output

Your screen recording is 16:9 (1920×1080). But Instagram Reels and TikTok need 9:16 (1080×1920). A naive center-crop loses 56% of the width. If your zoom target is on the left side of the screen, it gets chopped off.

THE DANGER OF NAIVE CENTER-CROP

Source: 1920×1080. Target region: search bar at x=400 (left side).

Naive center-crop for 9:16: crop 607px wide from center (x=656 to x=1263).

Your search bar at x=400 is completely outside the crop window. The 9:16 video shows nothing relevant.

4.2 The Solution: Content-Aware Panning

The engine calculates where the 9:16 viewport must be positioned so the zoom target stays visible and centered.

# Smart crop calculation for 9:16
source_width = 1920
source_height = 1080
viewport_width = source_height * 9 / 16  # = 607.5px

target = regions["search_bar"]  # {x: 400, y: 20, w: 600, h: 80}
target_center_x = target["x"] + target["w"] / 2  # = 700

# Position viewport so target is centered
crop_x = target_center_x - viewport_width / 2  # = 700 - 303 = 397

# Clamp to frame bounds
crop_x = max(0, min(crop_x, source_width - viewport_width))
# = max(0, min(397, 1312)) = 397

# FFmpeg crop filter: crop=607:1080:397:0
# Result: The search bar is perfectly centered in the 9:16 frame

4.3 Layout Strategies

Strategy Behavior Use Case
center_crop Always crop from center. Target position ignored. Target is already near center. Simple and stable.
follow_target Pan crop window to keep zoom target centered. Target moves around the screen. Most common case.
safe_zone Keep content within brand-defined safe margins. Logo or critical UI near edges. Prevents cropping important elements.
manual_pan User specifies pan offset per scene in YAML. Advanced: fine-tune exactly where the crop sits.

4.4 YAML Configuration for Layout

project:
  name: "MyApp Demo"
  source_video: "source.mp4"
  output_name: "myapp_demo"
  fps: 30
  resolution: "1920x1080"

  # Layout configuration
  source_aspect: "16:9"           # Your recording's aspect ratio
  output_aspect: "9:16"         # What you need for social
  layout_strategy: "follow_target"  # center_crop | follow_target | safe_zone | manual_pan

  # Safe zone margins (pixels from edges that must not be cropped)
  safe_zone:
    top: 60
    bottom: 60
    left: 100
    right: 100

  export_formats:
    - "16:9"                      # Master render (full frame)
    - "9:16"                      # Vertical with smart panning
    - "1:1"                       # Square with smart centering

scenes:
  - id: "search_demo"
    time: "0:05 - 0:13"
    visual:
      type: "zoom"
      target: "search_bar"
      zoom_level: 2.0
      easing: "cubic_ease_in_out"
      # Optional: override layout for this scene
      layout_override:
        strategy: "follow_target"
        pan_offset: 0               # Additional horizontal shift (pixels)
    effects:
      - type: "callout_box"
        target: "search_bar"
        color: "#6C4EF5"
    subtitle:
      text: "Find anything instantly"
      style: "typewriter"
    transition_out:
      type: "crossfade"
      duration: "0.3s"

4.5 How the Engine Handles Layout

  1. Master render (16:9): Rendered normally. Full frame. All effects, zooms, subtitles applied at native resolution.
  2. 9:16 export: For each scene, calculate crop window position based on layout_strategy and the scene's target. Re-render the scene with the crop window offset. The zoom target stays centered in the vertical frame.
  3. 1:1 export: Similar to 9:16 but with square crop. Crop window is centered on target, then clamped to safe zones.
THE RESULT

A 16:9 source video with a search bar on the left side produces a 9:16 vertical video where the search bar is perfectly visible and centered. The crop window "follows" the action instead of blindly center-cropping. Your vertical videos look intentional, not accidentally cropped.

FEATURE Gemini Gem Script Composer

6.1 What the Gem Does

The Gem is a creative director that interviews you in plain English and outputs a complete, valid ZOVAC YAML script. It knows every valid enum value, every scene structure rule, and every constraint. It prevents errors before they happen.

6.2 Error Prevention Features

Error Type How Gem Prevents It
Missing regions At the end of conversation, Gem lists ALL region names used: "Before rendering, draw these regions: search_bar, dashboard, submit_button."
Invalid enum values Gem only outputs values from its known list. Never invents new easing curves or transition types.
Bad time format Gem always uses M:SS - M:SS format. Never outputs raw seconds or ambiguous formats.
Zoom level out of range Gem keeps zoom_level between 1.0 and 5.0. Suggests 2.0 as default.
Duration missing "s" Gem always appends "s" to durations: "0.6s", "1.0s".
YAML syntax errors Gem outputs properly indented YAML with correct list syntax (- prefix).
Scene ID with spaces Gem uses snake_case for IDs: "search_bar_demo" not "search bar demo".
Overlapping time ranges Gem ensures each scene starts where the previous one ends. No gaps, no overlaps.

6.3 Gem Conversation Flow

Phase 1: Project Basics

Gem asks:

  • "What is the name of your project?"
  • "What is your screen recording file called?" (default: source.mp4)
  • "What should the final video be called?" (slug version of project name)
  • "What frame rate? 24fps (cinematic), 30fps (standard), or 60fps (smooth)?" (default: 30)
  • "Resolution? Usually 1920x1080 is perfect." (default: 1920x1080)
  • "What layout? 16:9 only, or also 9:16 for Reels/TikTok, or 1:1 for Instagram?"

Phase 2: The Story

Gem asks: "Tell me about your video. Walk me through what happens in the recording like you are describing it to a friend. What is the main message? What should viewers feel?"

Gem listens for: the problem, the wow moment, the emotional goal.

Phase 3: Scene by Scene

For each scene, Gem asks in order:

  • "When does this happen? Like 0:05 to 0:12." (time format: M:SS - M:SS)
  • "Do you want to show the whole screen or zoom into something specific?"
  • If zoom: "What region? (You will draw this later in the region helper)"
  • If zoom: "How close? 1.5x is subtle, 3x is very close."
  • "What should the subtitle say?"
  • "How should the text appear? Fade in word-by-word (smooth), typewriter (classic), slide up (energetic), or just fade in?"
  • "How should this scene end? Crossfade (smooth), wipe (directional), zoom blur (dramatic), or flash cut (punchy)?"

Gem proactively suggests effects: "Want a glowing box around that button?" "Want everything else dimmed so this stands out?" "Want an arrow pointing to it with a label?"

Phase 4: Review and Generate

Gem summarizes all scenes in plain English. Asks: "Does this sound right?"

Then outputs:

  1. Complete YAML script
  2. List of region names: "Before rendering, use region_helper.py to draw these regions: [list]"
  3. Instructions: "Save this as projects/YOUR_PROJECT/script.yaml, then draw regions, then run the render command."

6.4 Gem System Prompt

Paste this into Google AI Studio when creating your Gem:

# ZOVAC Script Composer — System Prompt

You are a creative video director helping users create YAML scripts for ZOVAC Memark Pro, a tool that turns boring screen recordings into polished product videos with smooth zooms, callout boxes, and animated text.

## Your Role
Interview the user in plain English about their video idea, then output a complete YAML script they can use.

## Conversation Flow (4 Phases)

### Phase 1: Project Basics
Ask one or two questions at a time:
- "What is the name of your project?"
- "What is your screen recording file called?" (default: source.mp4)
- "What should the final video be called?" (suggest lowercase slug)
- "Frame rate: 24fps (cinematic), 30fps (standard), or 60fps (smooth)?" (default: 30)
- "Resolution: 1920x1080?" (confirm or ask)
- "Export formats: 16:9 only, or also 9:16 for Reels/TikTok, or 1:1?"

### Phase 2: The Story
- "Tell me about the video. Walk me through what happens like you are describing it to a friend."
- "What is the main message? What should the viewer feel or do after watching?"
- "Who is the audience — customers, investors, your team?"

### Phase 3: Scene by Scene
For each scene, ask in this order (one or two per message):

**Timing:** "When does this part happen? Give me start and end time — like 0:05 to 0:12."

**Focus:** "What is showing during this part? Whole screen or zoom into something specific?"
- If zoom: "What region? Give it a name like search_bar or submit_button."
- If zoom: "How close? 1x = normal, 2x = gentle zoom, 3-4x = very close."

**Camera:** "Should it zoom in (zoom), slowly slide across (pan), zoom in dramatically (dolly_in), or show full screen (fullscreen)?"

**Easing:** "Should it feel slow and silky smooth, or snappy and energetic?"
- Maps to: cubic_ease_in_out (smooth) or ease_in_out (snappy)

**Effects:** "Want to draw a glowing box around something? Point an arrow at it? Dim everything else?"
- callout_box, annotation_arrow, spotlight

**Subtitle:** "What should the subtitle say in this scene?"

**Subtitle Style:** "Should words appear all at once, one by one, or typed out?"
- fade_in, fade_in_word_by_word, typewriter, slide_up, highlight_current_word

**Transition:** "How should this scene flow to the next? Smooth fade, dramatic zoom blur, wipe, or hard cut?"
- crossfade, smooth_zoom_in, zoom_out_blur, zoom_blur_push, wipe_left, wipe_up, flash_cut, none

Use smart defaults silently and mention them:
- "I will default that to a smooth crossfade."
- "I will set zoom_level to 2.0 as a good starting point."

### Phase 4: Review and Generate
Give a plain-English summary of every scene. User confirms.

Then output:
1. Complete YAML script
2. Message: "Here is your complete ZOVAC script! Copy this and save it as projects/YOUR_PROJECT_NAME/script.yaml"
3. Message: "IMPORTANT: Before rendering, run the region helper to draw these regions: [list all target names]"
4. Message: "Then run: python engine/render.py --script projects/YOUR_PROJECT/script.yaml --regions projects/YOUR_PROJECT/regions.json --output-dir projects/YOUR_PROJECT/output"

**Easing:** linear, ease_in, ease_out, ease_in_out, cubic_ease_in_out, ease_in_out_sine, spring, bounce_out

**Visual type:** fullscreen, zoom, pan, dolly_in, dolly_out

**Effect type:** callout_box, annotation_arrow, spotlight, motion_blur

**Subtitle style:** fade_in, fade_in_word_by_word, typewriter, slide_up, highlight_current_word

**Subtitle position:** top_center, center, bottom_center, top_left, bottom_left

**Transition type:** crossfade, smooth_zoom_in, zoom_out_blur, zoom_blur_push, wipe_left, wipe_up, flash_cut, none

**Zoom level:** 1.0 to 5.0 (default: 2.0)

**Duration format:** Float + "s" (e.g., "0.6s")

**Time format:** M:SS - M:SS or HH:MM:SS - HH:MM:SS

PERSONAL Architecture

7.1 The Three Components

1. Gemini Gem (Script Composer)
You describe your video idea in plain English. The Gem interviews you about timing, zoom targets, effects, and subtitles. It outputs a complete YAML script. You copy-paste it into a file.
2. Region Helper (Python Script)
A small Python script using OpenCV. It opens your video frame. You click-and-drag to draw boxes around UI elements. It saves coordinates to a JSON file. You can re-open it to add or edit regions.
3. Pixel Engine (Python Application)
The main renderer. Reads your YAML script, your video file, your regions JSON, and your brand config. Produces frame-by-frame rendered output with smooth zooms, callout effects, animated subtitles, and transitions. Outputs a polished MP4.

7.3 No Network Required After Setup

OFFLINE CAPABLE

Once the Gem is set up and the engine is installed, you can create videos completely offline:

  • Write YAML by hand (no Gem needed if you know the syntax)
  • Draw regions with the helper (pure OpenCV, no internet)
  • Render with the engine (Python + FFmpeg, no API calls)

The Gem is a convenience, not a requirement. You can write YAML manually anytime.

10.4 Tips for Best Results

  • Record in good lighting: Your screen should be bright and readable. Dark themes work better than light themes for video.
  • Keep mouse movement smooth: Jerky cursor movement looks amateur. Move deliberately, pause before clicks.
  • Record 10-20% extra: If you need 30 seconds of content, record 35 seconds. Gives you padding for transitions.
  • Use consistent UI scale: Do not change browser zoom or OS scaling mid-recording. Regions are pixel-based.
  • Name regions descriptively: "search_bar" is better than "box1". Helps the Gem and your future self.
  • Start with 2-3 scenes: Do not try to render a 10-scene epic on day one. Build complexity gradually.
  • Save brand.json templates: Once you find colors that work, save them as reusable brand profiles.
