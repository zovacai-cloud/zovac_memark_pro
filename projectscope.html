SEC 1 Product Vision

THE SINGLE PURPOSE

ZOVAC Memark Pro transforms boring screen recordings into Google-quality product showcase videos that make software look magical, effortless, and irresistible — without the user touching a single frame of video editing software.

1.1 The Problem We Solve

Screen recordings of software are the most honest way to show a product, but they are also the most boring. A raw screen recording has no narrative arc, no visual hierarchy, no emotional hook, and no production value. Viewers drop off within 3 seconds.

Meanwhile, creating a professional product video requires:

  • After Effects expertise (months to learn)
  • Motion graphics skills (keyframing, easing curves)
  • Sound design knowledge
  • Hours of manual timeline scrubbing
  • Expensive software subscriptions

ZOVAC Memark Pro eliminates all of this. The user uploads a screen recording, describes what they want in plain language (or structured YAML), and the engine produces a cinematic result.

SEC 2 What We Are Building

2.1 System Definition

ZOVAC Memark Pro is a template-driven video compositor with a cinematic editing engine. It is not a real-time video editor. It is not a generative AI video creator. It is a directional rendering engine that takes structured creative instructions and applies them frame-by-frame to a source video.

⚡
The Analogy: "Figma for Video Production Directions"

Just as Figma lets designers describe UI layouts with vectors and constraints rather than painting pixels, ZOVAC lets creators describe video edits with structured directions rather than scrubbing timelines. The engine handles every frame.

2.2 What the System Is NOT (Explicit Exclusions)

Exclusion Why Future Version
No real-time timeline editor Timeline GUIs are massive engineering projects (DaVinci Resolve, Premiere). We bypass this entirely with YAML/script-driven rendering. V3 may add a visual timeline preview
No generative AI video creation Input is always a real screen recording. We do not generate pixels from text prompts. We enhance existing footage. Never — this is a core principle
No audio editing or voiceover sync Audio waveform analysis, voiceover alignment, and ducking are complex. V1 focuses on visual storytelling only. V2 may add auto-ducking and music beat-sync
No collaborative multi-user editing Real-time collaboration (Figma-style cursors, conflict resolution) is a separate product. V1 is single-user. V3 may add team workspaces
No cloud rendering (V1) All rendering happens locally via Python subprocess. No AWS Lambda, no queue systems, no billing for compute. V2 may offer optional cloud rendering

SEC 3 The Google-Style Video — Deconstructed

DEFINITION: "Google-Style Product Video"

A Google-style product video is not just "a video with zooms." It is a neurochemically optimized piece of visual communication designed to trigger curiosity, satisfaction, and desire within the first 3 seconds. Every frame serves a psychological purpose.

3.1 The Six Psychological Hooks (Must Be Achievable)

3.1.1 Problem-First Storytelling

Within the first 2 seconds, the video shows a highly relatable, frustrating everyday problem. The viewer must think "That happens to me." This creates immediate emotional investment.

ZOVAC Implementation: The first scene of the YAML script should always be a fullscreen visual showing the "before" state — chaotic UI, too many tabs, manual work, confusion. Subtitle: "Still doing this manually?"

3.1.2 The "Magic" Reveal

The product is introduced as the instant, effortless solution to the specific frustration shown in the problem scene. The transition from problem to solution must feel like a magic trick.

ZOVAC Implementation: A zoom_blur_push or flash_cut transition from the "before" scene to the "after" scene. The cursor flies to the search bar. The subtitle types out: "Not anymore."

3.1.3 Flawless Motion Graphics

Clean UI animations, kinetic typography, and smooth camera movements make the software look fast, modern, and satisfying. There are no jerky cuts. Every movement has easing.

ZOVAC Implementation: All zooms use cubic_ease_in_out or spring easing. Text uses typewriter or fade_in_word_by_word animations. Callout boxes draw themselves with animated_stroke.

3.1.4 Kinetic Sound Design (V2 — Visual Prep Now)

Upbeat, rhythmic music synchronized with crisp sound effects (clicks, swooshes, whooshes) triggers a dopamine response. The video feels satisfying to watch.

ZOVAC V1 Implementation: The engine produces a silent MP4 with precise visual cues (cursor clicks, transitions, text appearances) timed to frame-accurate timestamps. In V2, we will overlay sound effects at these exact timestamps. The V1 output is designed to be "sound-ready."

3.1.5 Aspirational Framing

The video implies that using this tool makes the user more capable, more productive, more professional. The UI never looks cluttered. The colors are bold and confident.

ZOVAC Implementation: Brand profiles enforce high-contrast color palettes. The spotlight effect dims irrelevant UI, focusing attention only on the feature being showcased. The video never shows error states, loading spinners, or empty tables.

3.1.6 Frictionless Call to Action

The video ends by making the tool look entirely free, easy, and ready to use in one click. The final frame is a clean logo lockup with a URL or CTA button.

ZOVAC Implementation: The final scene of every script is a fullscreen visual with the brand logo (positioned per brand config), tagline subtitle with fade_in style, and no complex effects — just calm, confident presence.

3.3 The "Animated Cursor" — The Art of the Video

THE CURSOR IS THE PROTAGONIST

In a Google-style product video, the cursor is not a passive pointer. It is the narrator. It moves with purpose. It pauses before clicking to build anticipation. It flies between elements to show connectivity. It clicks with a subtle "press" animation (shrinks to 90% size then bounces back).

ZOVAC V1: We render a custom cursor overlay that follows a path defined in the YAML script. The cursor has a brand-colored glow trail. It clicks at specified timestamps. In V1.5, we add 3D tilt to the cursor when it moves fast.

3.4 What "My Tools" Means in This Context

You have built software tools (apps, dashboards, utilities). You want to show the impact they have created — not just the interface, but the transformation they enable.

Example narrative arc for a tool:

  1. Problem Scene (0:00-0:05): Show a messy spreadsheet, a cluttered inbox, a frustrated user. Subtitle: "Managing inventory used to take 4 hours."
  2. Reveal Scene (0:05-0:12): Zoom to your app's dashboard. Cursor flies to the search bar. Types a query. Results appear instantly. Subtitle: "Now it takes 4 seconds."
  3. Feature Deep-Dive (0:12-0:25): Callout boxes highlight key features. Spotlight dims everything else. Arrow points from labels to UI elements. Cursor demonstrates 2-3 core actions.
  4. Impact Scene (0:25-0:35): Show a chart, a notification, a success state. 3D floating element (a trophy icon or checkmark) celebrates the win. Subtitle: "10,000+ teams already switched."
  5. CTA Scene (0:35-0:40): Clean logo lockup. URL appears. Subtitle: "Try it free."

SEC 5 Node Overview — The Build Sequence

We do not build layers. We build nodes — vertical slices that each produce a working, testable artifact. Each node is a complete mini-product that can be built, tested, and documented independently. The output of Node N becomes the input of Node N+1.

BUILD PRINCIPLE: NO NODE IS COMPLETE UNTIL IT IS DEMONSTRABLY WORKING

Before moving to Node N+1, Node N must pass its exit criteria: a real file must be produced, a real API call must succeed, a real video must play. No "we'll test it later." No "the next node will fix it."

6.1.4 Internal Pipeline (7 Steps)

Step 1/7: Parse Script
parser.py
Read YAML → Python dict. Validate syntax. Extract project metadata, scenes list, export formats, brand profile slug.
Step 2/7: Check Source Video
validator.py
os.path.exists(source_video). If missing: log [ERROR] Source video not found: {path} and exit(3).
Step 3/7: Load Regions
parser.py
Read regions JSON. Empty dict is valid. Scenes using fullscreen do not need regions.
Step 4/7: Load Brand
brand.py
Read brand JSON. If path is None or file missing: use DEFAULT_BRAND (hardcoded fallbacks).
Step 5/7: Validate Script
validator.py
Check: all targets exist in regions or equal "fullscreen". All easing values valid. All transition types valid. All subtitle styles valid. zoom_level in [1.0, 5.0]. Durations end in "s". Returns (is_valid, errors[], warnings[]). If not valid: print errors and exit(1).
Step 6/7: Render Scenes
compositor.py + effects.py + motion.py + subtitles.py
For each scene: extract subclip from source video (frame-accurate seeking), apply zoom/pan transform, overlay effects (callout, arrow, spotlight, blur), burn subtitles with animation style, write temp clip to disk. Collect all temp clip paths.
Step 7/7: Assemble & Export
transitions.py + exporter.py
Apply transitions between scene clips (crossfade, wipe, zoom blur). Concatenate into master timeline. Export master MP4. Then crop/scale to 9:16 and 1:1 formats. Write all files to output_dir.

It receives a render request from the frontend, gathers all necessary inputs from the database, writes them to disk in the format the Python engine expects, spawns the engine as a subprocess, captures its output, and reports status.

6.3.2 What It Receives (Input Contract)

6.3.3 The Critical Path-Patching Step (BUG THAT MUST NEVER REGRESS)

THE SOURCE_VIDEO PATCH — NON-NEGOTIABLE

The YAML script stores source_video: "original_name.mp4" (the filename for display). The Python engine needs the full absolute disk path to find the file.

Before every render, the API MUST patch the YAML:

scriptYaml = scriptYaml.replace(
    /source_video:\s*.+/,
    `source_video: "${project.sourceVideo}"`
);

Where project.sourceVideo is the full absolute path from the assets table (e.g., /home/user/zovac/uploads/assets/1747123456_myapp_demo.mp4).

Without this patch, every render fails with "Source video not found."

6.3.4 What It Produces (Output Contract)

Output Type Contract
jobId integer The render_jobs.id created before spawning Python.
status string "started" immediately. Then DB is updated to rendering, completed, or failed.
outputPaths JSON object Updated in DB after render completes: {"16:9": "...", "9:16": "...", "1:1": "..."}
progress integer 0-100 Parsed from Python stdout X/Y patterns. Updated every 3-5 seconds.

6.3.5 Subprocess Management Rules

  • Python is spawned with spawn("python3", pythonArgs, { cwd: engineDir }).
  • stdout is read line-by-line via python.stdout.on("data", ...).
  • Progress is extracted via regex: /^(\d+)\/(\d+)/ matching lines like "3/7 Rendering scenes...".
  • A render timeout of 10 minutes is enforced. If Python hangs, it is killed and job marked failed.
  • Cancellation must kill the Python process via python.kill(), not just update DB status.
  • On Python exit code 0: mark completed, parse output paths, store in DB.
  • On Python exit code 1/2/3: mark failed, store last 500 chars of stderr in errorMessage.

N6 The Script Composer (Gemini Gem)

6.6.1 Role & Purpose

The Script Composer is a custom Gemini Gem (system-prompted AI assistant) that acts as a creative director. Non-technical users talk to it in plain English, describe their video vision, and it outputs a perfectly structured YAML directions script that ZOVAC can render directly.

6.6.2 Conversation Flow (4 Phases)

Phase Purpose Example Interaction
Phase 1: Project Basics Gather metadata: project name, source video filename, output name slug, FPS, resolution, export formats, brand profile. "What would you like to name this video project?" → "MyApp Demo"
Phase 2: Video Story Understand the narrative arc: what happens in the recording, main message, target audience, emotional goal. "Tell me about the video. Walk me through what happens like you're describing it to a friend."
Phase 3: Scene by Scene For each scene: timing, focus target, zoom level, camera type, easing feel, effects, subtitle text, subtitle style, transition. "When does this part happen? Like 0:05 to 0:12." → "What should the subtitle say?" → "Should words appear all at once or one by one?"
Phase 4: Review & Generate Gem gives plain-English summary of every scene. User confirms. Gem outputs complete YAML. Warns user to draw region boxes before rendering. "Here's your complete ZOVAC script! Copy this into the Script tab. Important: Before rendering, go to the Regions tab and draw boxes for these region names you used: [list]."

6.6.3 Gem Personality Rules

  • Always friendly, warm, encouraging — never technical or robotic.
  • Ask one or two questions at a time maximum. Never dump a full form.
  • Rephrase every technical question into plain English.
  • After each scene: confirm with a human-readable summary before moving on.
  • Use smart defaults silently: "I'll default that to a smooth crossfade" — mention what was defaulted.
  • Never expose YAML syntax to the user mid-conversation. Output YAML only at the very end.

The Gem must know every valid value from Section 6.2 of this document:

  • Easing: linear, ease_in, ease_out, ease_in_out, cubic_ease_in_out, ease_in_out_sine, spring, bounce_out
  • Visual type: fullscreen, zoom, pan, dolly_in, dolly_out
  • Effect type: callout_box, annotation_arrow, spotlight, motion_blur
  • Subtitle style: fade_in, fade_in_word_by_word, typewriter, slide_up, highlight_current_word
  • Subtitle position: top_center, center, bottom_center, top_left, bottom_left
  • Transition type: crossfade, smooth_zoom_in, zoom_out_blur, zoom_blur_push, wipe_left, wipe_up, flash_cut, none

N7 The Polish Layer

6.7.1 Role & Purpose

The Polish Layer adds advanced cinematic effects that elevate the video from "good" to "Google-quality." These effects require more complex math, 3D transforms, or audio analysis. They are built after the core pipeline (N1-N5) is stable.

6.7.2 Planned Effects (V1.5 / V2)

Effect Description Technical Approach
3D Floating Element A UI element (logo, icon, screenshot) lifts off the screen with perspective tilt, casts a shadow, and floats across the frame. OpenCV perspective transform (homography) + Pillow shadow blur + frame-by-frame position interpolation with easing.
Animated Cursor Trail A glowing cursor moves along a path, leaving a fading trail. It clicks with a bounce animation. Bezier path interpolation between region centers. Cursor drawn as overlay on each frame. Trail is a decaying series of past cursor positions with decreasing opacity.
Sound Effect Sync Visual events (clicks, transitions, text appearances) are marked with timestamp metadata. A post-process step overlays sound effects at these exact frames. Engine emits a sync_points.json file with timestamps and event types. A second FFmpeg pass overlays MP3 sound effects at these times.
Music Beat Detection Background music is analyzed for beat peaks. Transitions and text animations are snapped to the nearest beat for rhythmic satisfaction. Librosa (Python) beat detection on uploaded music file. Transition durations adjusted to match beat intervals.
Auto-Subtitle from Audio If the source video has narration, Whisper transcribes it and generates subtitle YAML automatically. OpenAI Whisper (local) → SRT → ZOVAC subtitle blocks with default fade_in style.
Motion Blur on Camera Moves Directional blur applied only during fast zoom/pan movements, simulating real camera shutter speed. Measure inter-frame displacement. Apply directional Gaussian blur proportional to velocity vector.

7.1 The Complete Render Flow (End-to-End)

Step 1: User Creates Project
FRONTEND → API
User drops video on Dashboard → FileReader → base64 → assets.upload → API writes file to disk → returns { path, publicUrl } → projects.create → DB stores project with sourceVideo=absolute path.
Step 2: User Maps Regions
FRONTEND → API
User opens Regions tab → canvas draws video frame → user draws boxes → coords scaled to video pixel space → projects.update({ regionsJson }) → DB stores regions.
Step 3: User Writes Script
FRONTEND → API
User writes YAML in Script tab (or copies from Gem) → auto-save debounced → projects.update({ scriptYaml }) → DB stores script. Validate button checks regions and enums client-side.
Step 4: User Clicks Render
FRONTEND → API → PYTHON
Frontend calls renders.start({ projectId, jobType: "full" }) → API creates render_jobs row (status=queued) → API fetches project (scriptYaml, sourceVideo, regionsJson, brandProfileId) → API patches source_video path in YAML → API writes script YAML to disk → API writes regions JSON to disk → API writes brand JSON to disk → API spawns Python with all file paths → API updates status to "rendering".
Step 5: Python Engine Runs
PYTHON → DISK
Python reads YAML + video + regions + brand → validates → renders scenes frame-by-frame → applies transitions → exports master + 9:16 + 1:1 → writes MP4s to disk → emits progress lines to stdout → exits 0 on success, 1/2/3 on failure.
Step 6: API Captures Result
API → DB
API reads Python exit code → if 0: parses outputPaths from known directory structure → updates render_jobs: status=completed, progress=100, outputPaths=JSON, completedAt=now. If non-zero: status=failed, errorMessage=last 500 chars of stderr.
Step 7: User Downloads Video
FRONTEND → API → DISK
Frontend polls renders.listByProject every 3 seconds → sees completed job → shows download links → user clicks <a href="/api/renders/:id/download/16:9"> → Hono HTTP route streams MP4 from disk with Content-Disposition: attachment.

7.2 Critical Data Contracts

Contract A: File Path Contract

THE PATH CONTRACT — NEVER VIOLATE
Source Video Path (DB → API → Python)
Always the full absolute disk path. e.g., /home/user/zovac/uploads/assets/1747123456_demo.mp4. Never a relative path. Never just a filename.
Public URL (API → Frontend → Browser)
Always an HTTP-relative URL. e.g., /uploads/assets/1747123456_demo.mp4. Used in <video src> and <a href>. Served by Hono GET /uploads/*.
YAML source_video Field
Stores the original filename for display (e.g., "demo.mp4"). The API patches this to the absolute path before writing the script to disk for Python.
Output Paths
Absolute paths stored in render_jobs.outputPaths JSON. Frontend never sees these directly. Frontend uses /api/renders/:id/download/:format which looks up the path server-side.

Contract B: Progress Reporting Contract

Python stdout format
Lines must match /^(\d+)\/(\d+)\s+(.*)/. Example: "3/7 Rendering scenes...". The first capture group is current step, second is total steps. Description is ignored by parser but shown in logs.
API parsing
API reads stdout line-by-line. Extracts X/Y. Calculates progress = (X / Y) * 100. Updates DB every 5 seconds or every line (whichever is slower).
Frontend polling
Frontend uses useQuery({ refetchInterval: 3000 }) while any job status is rendering or preview. In React Query v5, the refetchInterval function receives a Query object, not the data directly. Correct usage: refetchInterval: (query) => { const list = query.state.data; ... }.

Contract C: Region Coordinate Contract

Storage Format
JSON object: { "region_name": { "x": int, "y": int, "w": int, "h": int } }. All values are integers. Origin is top-left (0,0).
Coordinate Space
All coordinates are in source video pixel space. If source video is 1920×1080, a region at the center might be {"x": 860, "y": 490, "w": 200, "h": 100}.
Canvas Scaling
Frontend canvas display size ≠ video size. When user draws on canvas: stored_x = canvas_x * (videoWidth / canvas.offsetWidth). When redrawing: canvas_x = stored_x * (canvas.offsetWidth / videoWidth).
Engine Usage
Python engine reads regions JSON and uses coordinates directly. No scaling needed in Python because coordinates are already in video pixel space.

Contract D: Brand Config Contract

Storage Format
JSON string in brand_profiles.config (DB). Also written to disk as uploads/brands/{slug}.json before render.
Schema
See Section 10 of this document for complete Brand Config JSON Structure.
Default Fallback
If no brand profile is assigned, or if brand JSON file is missing, engine uses DEFAULT_BRAND hardcoded in brand.py. Default colors: primary=#6C4EF5, secondary=#1DE9B6, text_light=#FFFFFF, text_dark=#1A1A2E.

SEC 11 Build Order — The Node Sequence

BUILD PRINCIPLE: VERTICAL SLICES, NOT HORIZONTAL LAYERS

We do not build "the database" then "the API" then "the frontend." We build Node 1 (a working video renderer), prove it works with a real MP4, then build Node 2 (file upload), prove a file can reach the server, then connect them in Node 3. Each node is a complete, testable artifact.

# Node 1: The Pixel Engine
# Status: COMPLETE
# Built By: Session Alpha
# Date Completed: 2026-05-25

## 1. What This Node Does
The Pixel Engine is a standalone Python application that reads a ZOVAC YAML script,
a source video file, a region map JSON, and a brand config JSON. It produces
frame-by-frame rendered video output with smooth camera zooms, visual effects
(callout boxes, arrows, spotlights), animated subtitles, and scene transitions.
It is the heart of ZOVAC Memark Pro — everything else exists to feed it data.

## 2. Files Created
- `engine/render.py` — CLI entry point. Parses args, orchestrates pipeline.
- `engine/script_parser.py` — YAML parsing, time string parsing (SS, MM:SS, HH:MM:SS).
- `engine/compositor.py` — Frame extraction via FFmpeg, pixel operations, temp clip writing.
- `engine/effects.py` — callout_box, annotation_arrow, spotlight, motion_blur.
- `engine/subtitles.py` — fade_in, typewriter, fade_in_word_by_word, slide_up, highlight_current_word.
- `engine/motion.py` — zoom, pan, dolly_in, dolly_out with 8 easing curves.
- `engine/transitions.py` — crossfade, smooth_zoom_in, zoom_out_blur, zoom_blur_push, wipe_left, wipe_up, flash_cut.
- `engine/exporter.py` — Multi-format export: master, 16x9, 9x16, 1x1.
- `engine/validator.py` — Script validation against regions and enums.
- `engine/brand.py` — Brand profile loading with DEFAULT_BRAND fallback.
- `engine/requirements.txt` — Python dependencies.

## 3. Architecture Decisions
- Used Pillow (PIL) for text rendering instead of MoviePy TextClip because Pillow
  gives pixel-perfect control over font loading, kerning, and multi-line wrapping.
- Used OpenCV for frame transforms (zoom, pan) because warpAffine is faster than
  PIL's transform for video-scale operations.
- Used FFmpeg subprocess for frame extraction instead of OpenCV VideoCapture
  because FFmpeg handles more codecs reliably and supports accurate seeking.
- Placed -ss AFTER -i in FFmpeg args for frame-accurate seeking (fixes BUG-012
  from previous attempt).

## 4. Input Contract
- `--script`: Absolute path to YAML file following ZOVAC Schema v1.0
- `--regions`: Absolute path to JSON file with region definitions (can be empty object)
- `--brand`: Absolute path to brand config JSON (optional, null = DEFAULT_BRAND)
- `--output-dir`: Absolute path to directory for output files
- `--preview`: Flag. If present, render at 24fps, 960x540, max 20 seconds.
- `--scene`: String. If present, render only the scene with this id.

## 5. Output Contract
- `{output_dir}/{output_name}_master.mp4` — 16:9 master render
- `{output_dir}/16x9/{output_name}_16x9.mp4` — 16:9 copy
- `{output_dir}/9x16/{output_name}_9x16.mp4` — 1080x1920 vertical crop
- `{output_dir}/1x1/{output_name}_1x1.mp4` — 1080x1080 square crop
- stdout: Progress lines in "X/Y Description..." format
- stderr: Errors and warnings
- Exit code: 0=success, 1=validation, 2=render, 3=missing video

## 6. Test Results
- Test video generator created 15-second fake app UI at 1920x1080 30fps.
- Demo YAML with 3 scenes rendered successfully in 1m 42s on M1 MacBook Air.
- Output MP4 verified in VLC: zoom smooth, text types, callout draws, crossfade visible.
- Frame timestamp verified with ffprobe: scene at 0:05 starts at exactly 5.000s.

## 7. Known Limitations
- Does not support audio overlay (V1.5).
- Does not support 3D floating elements or cursor trails (V1.5 / Node 7).
- Motion blur applies to whole frame, not directional (V1.5).
- 9:16 crop uses center-crop; does not intelligently track moving subjects.

## 8. Connection to Next Node
Node 2 (File Gateway) will provide the source video file path.
Node 3 (Trigger Bridge) will call this engine via subprocess, passing the file paths.
